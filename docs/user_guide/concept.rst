.. _concept:

======================
Концепция библиотеки
======================

Библиотека построена вокруг трёх объектов. Метрика это функция с едиными аргументами и метаданными. Диспетчер выбирает реализацию по типу входа. Результат это объект с самим значением и сведениями о том, как оно получено.

Единый вызов
--------------

У каждой метрики есть пары ``obs`` и ``sim``, а также общие аргументы:

.. list-table::
   :header-rows: 1
   :class: hm-table
   :widths: 28 72

   * - Аргумент
     - Смысл
   * - ``axis`` / ``dim``
     - Измерение, вдоль которого считается метрика; см. :doc:`axes`.
   * - ``nan_policy``
     - Политика пропусков: ``omit`` (умолчание), ``propagate``, ``raise``; см. :doc:`missing_values`.
   * - ``sample_weight`` / ``weight``
     - Веса пар; см. :doc:`weights`.
   * - ``reduction``
     - Свёртка результата: ``mean``, ``sum`` или ``none``.
   * - ``align``
     - Выравнивание рядов с метками: ``strict`` (умолчание) или ``inner``; см. :doc:`input_data`.

Метрики со своими параметрами (``norm``, ``eps``, ``m``, ``fair``, ``ref_date``, ``dates`` и другие) описаны на страницах метрик. Сигнатуры и докстринги формируются из общего описания, поэтому ``help(hm.nse)`` показывает все параметры, а не безымянные ``**kwargs``.

Метаданные метрики
--------------------

Каждая метрика знает своё имя, направление улучшения, границы значений, ссылку на источник и формулу. Эти сведения попадают в результат и в сводные таблицы документации.

.. testcode::

   import numpy as np
   import hydrometrics as hm

   rng = np.random.default_rng(42)
   dates = np.arange("2010-10-01", "2013-10-01", dtype="datetime64[D]")
   doy = (dates - dates.astype("datetime64[Y]")).astype(int)
   # Половодье в конце апреля поверх зимней и летней межени, м³/с
   q_obs = 12 + 240 * np.exp(-(((doy - 118) / 16.0) ** 2)) + rng.gamma(2.0, 2.5, doy.size)
   # Модель запаздывает на двое суток и срезает пик
   q_sim = np.clip(0.88 * np.roll(q_obs, 2) + 3 + rng.normal(0, 5, doy.size), 0.1, None)

.. testcode::

   result = hm.kge_2012(q_obs, q_sim)
   print(result.name)
   print(result.direction, result.bounds)
   print(result.reference)

.. testoutput::

   maximize (-inf, 1.0)

Диспетчер и бэкенды
---------------------

Публичная функция, например ``hydrometrics.nse``, это диспетчер: по типу ``obs`` и ``sim`` он выбирает numpy, pandas, polars или xarray. Расчёт во всех случаях выполняет одно и то же ядро на numpy-массивах, а бэкенд только переводит вход и упаковывает результат. Поэтому значения не зависят от бэкенда; это проверяют парные тесты. Подробнее: :doc:`backends`.

Объект результата
-------------------

Результат это :class:`~hydrometrics.MetricResult`: значение, метаданные метрики, использованные параметры и сведения об удалённых пропусках. Подробнее: :doc:`results`.
