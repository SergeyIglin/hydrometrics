.. _metric-regNSE:

===========================================
Режимный критерий Нэша–Сатклиффа (regNSE)
===========================================

regNSE сравнивает годовые кривые обеспеченности наблюдённых и модельных расходов: значения каждого календарного года ранжируются по убыванию независимо друг от друга. Мерой служит сумма квадратов разностей одноимённых рангов, отнесённая к отклонению наблюдений от кривой обеспеченности среднего многолетнего гидрографа.

Сигнатура
-----------

.. code-block:: python

   hydrometrics.regNSE(obs, sim, *, dates, regime=None, axis=None, nan_policy="omit",
       sample_weight=None, weight=None, reduction=None, align="strict")

Запись в справочнике API: :func:`hydrometrics.regNSE`. На xarray вместо ``axis`` используется ``dim``; остальные параметры одинаковы на всех бэкендах.

Математическое определение
----------------------------

.. math::

   \mathrm{regNSE} = 1 - \frac{\sum_{y=1}^{Y}\sum_{k=1}^{365}\left(S_{(y,k)} - O_{(y,k)}\right)^2}{\sum_{y=1}^{Y}\sum_{k=1}^{365}\left(O_{(y,k)} - Q^{\mathrm{reg}}_k\right)^2}

:math:`O_{(y,k)}` и :math:`S_{(y,k)}` это :math:`k`-е по убыванию наблюдённое и модельное значение календарного года :math:`y`, :math:`Y` число лет, :math:`Q^{\mathrm{reg}}_k` :math:`k`-я ордината кривой обеспеченности среднего многолетнего гидрографа (средние по календарным дням, отсортированные по убыванию). Суммы объединяются по всем годам и рангам; осреднения по годам нет. В коде источником метрики указан Гарцман :footcite:p:`gartsman2023`; формула здесь взята из реализации, а не из статьи.

Отличия от классического определения
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

От :ref:`metric-nse` метрика отличается тремя чертами: значения ранжируются, поэтому порядок во времени теряется; опорой служит кривая обеспеченности режима, а не среднее; суммы объединяются по годам. Неполный год заполняет только первые ранги, остальные ординаты в сумму не входят. Правило для 366 дней одно: если есть високосный год, ранги 365 и 366 (два наименьших значения) усредняются до 365 рангов.

Это же правило применяется к кривой режима: для ряда с високосным годом 366 календарных средних сортируются по убыванию, и ранги 365 и 366 усредняются (ранги, а не календарные дни). Для годовых кривых и для кривой режима правило одинаково.

Диапазон значений и оптимум
-----------------------------

   * - Диапазон
     - Оптимум
     - Направление
   * - (-∞, 1]
     - 1
     - больше лучше

Значение 1 достигается, когда годовые кривые обеспеченности модели и наблюдений совпадают. Значение 0 соответствует модели, у которой в каждом году кривая обеспеченности равна кривой режима: тогда числитель равен знаменателю. Снизу значение не ограничено. Если все наблюдения постоянны, знаменатель равен нулю и результат равен NaN.

Интерпретация и критерии оценки
---------------------------------

Общепринятых градаций качества для regNSE в прочитанных источниках нет. Порогов для неё в прочитанной литературе не найдено; значения следует сопоставлять с NSE той же модели и с тем же режимом.

Значения в таблице отрицательны не из-за пропусков: ряд, на котором она посчитана, состоит из трёх похожих лет, а модельный ряд (``0.9 * obs + 4`` с шумом) отличается от наблюдений больше, чем наблюдения от кривой режима. Сравнивайте строки таблицы между собой, а не с примером ниже.

Пары с пропуском в ``obs``, ``sim`` или ``dates`` удаляются до ранжирования, поэтому при ``omit`` у обоих рядов остаются одни и те же даты. ``propagate`` возвращает NaN, ``raise`` вызывает ``ValueError``. Значение ``inf`` в ``obs`` даёт NaN.

Двумерный ввод вызывает ``ValueError``: метрика определена только для одномерного ряда. Расчёт по створам выполняется в цикле.

Примеры
---------

Три календарных года суточных расходов, 1096 значений. Модель запаздывает на двое суток, но воспроизводит распределение расходов внутри года.

.. testcode::

   import numpy as np
   import hydrometrics as hm

   rng = np.random.default_rng(42)
   # Календарные годы целиком: regNSE ранжирует значения внутри календарного года
   dates = np.arange("2010-01-01", "2013-01-01", dtype="datetime64[D]")
   doy = (dates - dates.astype("datetime64[Y]")).astype(int)
   # Половодье в конце апреля поверх зимней и летней межени, м³/с
   q_obs = 12 + 240 * np.exp(-(((doy - 118) / 16.0) ** 2)) + rng.gamma(2.0, 2.5, doy.size)
   # Модель запаздывает на двое суток, амплитуду воспроизводит
   q_sim = np.clip(np.roll(q_obs, 2) + rng.normal(0, 1, doy.size), 0.1, None)

.. testcode::

   reg = hm.regNSE(q_obs, q_sim, dates=dates)
   print(f"regNSE = {float(reg):.3f}, NSE = {float(hm.nse(q_obs, q_sim)):.3f}")

.. testoutput::
   :options: +NORMALIZE_WHITESPACE

   regNSE = 0.906, NSE = 0.974

Порядок во времени внутри года для regNSE не важен: после случайной перестановки модельных значений внутри каждого календарного года NSE становится отрицательной, а regNSE остаётся прежней, потому что набор значений года не меняется.

.. testcode::

   years = dates.astype("datetime64[Y]").astype(int) + 1970
   q_shuffled = q_sim.copy()
   for year in np.unique(years):
       inside = np.flatnonzero(years == year)
       q_shuffled[inside] = rng.permutation(q_sim[inside])
   reg_shuffled = float(hm.regNSE(q_obs, q_shuffled, dates=dates))
   nse_shuffled = float(hm.nse(q_obs, q_shuffled))
   print(f"regNSE = {reg_shuffled:.3f}, NSE = {nse_shuffled:.3f}")

.. testoutput::
   :options: +NORMALIZE_WHITESPACE

   regNSE = 0.906, NSE = -1.040

Знаменатель мал, когда годы похожи друг на друга и близки к кривой режима. Модель без запаздывания, но с завышением всех расходов на 15 %, получает по NSE хорошую оценку, а по regNSE гораздо худшую.

.. testcode::

   q_biased = 1.15 * q_obs
   reg_biased = float(hm.regNSE(q_obs, q_biased, dates=dates))
   nse_biased = float(hm.nse(q_obs, q_biased))
   print(f"regNSE = {reg_biased:.3f}, NSE = {nse_biased:.3f}")

.. testoutput::
   :options: +NORMALIZE_WHITESPACE

   regNSE = -42.174, NSE = 0.967

Кривую обеспеченности режима можно передать явно, например из более длинного ряда. Здесь она построена по этим же трём годам, поэтому результат не меняется.

.. testcode::

   regime = hm.mean_annual_hydrograph_duration_curve(q_obs, dates)
   print(regime.shape, round(float(hm.regNSE(q_obs, q_sim, dates=dates, regime=regime)), 3))

.. testoutput::
   :options: +NORMALIZE_WHITESPACE

   (365,) 0.906

Значения по отдельным календарным годам при общей кривой режима. Для группировки :func:`~hydrometrics.compute_grouped` здесь не подходит, потому что ``dates`` придётся передавать целиком; срез делается вручную.

.. testcode::

   for year in np.unique(years):
       inside = years == year
       value = hm.regNSE(q_obs[inside], q_sim[inside], dates=dates[inside], regime=regime)
       print(year, round(float(value), 3))

.. testoutput::
   :options: +NORMALIZE_WHITESPACE

   2010 0.883
   2011 0.905
   2012 0.928

На pandas даты передаются тем же аргументом; массив дат не проверяется и сопоставляется по позиции.

.. testcode::

   import pandas as pd

   series_obs, series_sim = pd.Series(q_obs), pd.Series(q_sim)
   print(round(float(hm.regNSE(series_obs, series_sim, dates=pd.to_datetime(dates))), 3))

.. testoutput::
   :options: +NORMALIZE_WHITESPACE

   0.906

Особенности применения в гидрологии
-------------------------------------

Метрика сравнивает распределения расходов внутри года, а не гидрографы по времени. В примере со случайной перестановкой модельных значений внутри года ``regNSE = 0.9057`` при ``NSE = -1.04``: модель с неверной фазой паводков может получить высокую оценку. Ошибку фазы regNSE не обнаруживает, для неё нужны :ref:`metric-nse` или :ref:`metric-kge_2012`.

Знаменатель regNSE это отклонение годовых кривых обеспеченности от кривой режима, и на реке со стабильным режимом он мал. Постоянное завышение расходов на 15 % даёт ``NSE = 0.9675``, но ``regNSE = -42.17``. Метрика строже NSE к смещению и объёму; сопоставляйте её с :ref:`metric-pbias`.

Ранжирование идёт внутри календарного года, а не водного. Год, в котором значений меньше 365, сравнивается только с самыми большими ординатами кривой режима, поэтому неполные первый и последний годы ряда искажают оценку. Подготовьте ряд из полных календарных лет или передайте режим явно.

Если ``regime`` не задан, кривая строится по тем же наблюдениям, которые оцениваются. На коротком ряду это делает опорную модель оптимистичной: для независимой оценки используйте кривую режима по более длинному периоду.
