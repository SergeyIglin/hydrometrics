# Changelog

Все заметные изменения пакета. Номера в скобках: пункты отчёта `docs/_dev/INVENTORY.md`
(раздел 5) и решения автора `Dn` из `task_2.txt`.

## 0.1.0 дата выпуска 05.11.2026

### Изменено поведение / Changed behavior

Изменения численных результатов и публичных сигнатур.

- Минимальная версия Python поднята до 3.10 (#31, D12): модуль `core/validation.py`
  вычисляет `A | B` над классами при импорте, что на 3.9 вызывает `TypeError`.

- Исключения больше не заворачиваются в `RuntimeError("Error computing ...")` (раздел 3.3, D9):
  вызывающий получает исходные `ValueError`, `TypeError`, `NotImplementedError`, `AxisError`.
  Код, перехватывавший `RuntimeError`, нужно поменять.

- `kge_2012` считает KGE′ по трём слагаемым `r`, `β`, `γ` (#34, #46). Прежняя форма добавляла
  четвёртое слагаемое `α`. Результат изменился: на данных `tests/test_baseline_values.py`
  0.8659 → 0.8913. Значения `kge_2012` из прежних версий несопоставимы с новыми.
- `alpha_component` и `kge_components` на всех бэкендах вызывают `ValueError` при `version`, не равном
  `"2009"` или `"2012"`; раньше pandas и polars молча принимали любое значение (#26, #27).

- `crps` для ансамбля: умолчание теперь классическая оценка (член разброса делится на `m²`), параметр
  `fair=True` возвращает прежнюю fair-оценку (`m(m−1)`) (#36, D3). Для ансамбля результат `crps`,
  `crpss` и `weighted_crps` увеличился (классическая оценка больше fair); детерминированный ввод не
  изменился. Новое: `crps(..., fair: bool = False)`.
- `crps` с ансамблем учитывает `axis` и `sample_weight`; `axis=0` на `(время, створ)` даёт форму
  `(створ,)`, а не `(время, створ)` (#17, #18). Ансамбль всегда на последней оси `sim`; прежняя
  недостижимая ветка «ось ансамбля = `axis`» удалена. На pandas, polars, xarray ансамблевый `crps`
  теперь возвращает скаляр, как numpy (раньше массив по срокам); значения по срокам даёт
  `reduction="none"` на numpy.
- `crpss` считает `1 − mean(CRPS)/mean(CRPS_ref)`, а не среднее отношений, также при ансамблевом
  `ref_forecast` (#15): на примере отчёта 0.3497 → 0.5033.
- `weighted_crps` работает с детерминированным `sim` при `weight_func` и `sample_weight` (раньше
  `ValueError`), веса применяются один раз как `weight_func(obs) * sample_weight` (#16, #17).
- `weighted_crps` и `r2` на пустом вводе и при всех NaN возвращают NaN, а не 0 и 1 (#23, #24).
- Взвешенное среднее в ядре учитывает в знаменателе только пары с допустимыми значением и весом.
  Меняет результат только при NaN во входе (#2, частично).
- `reliability`: прогноз `p = 1.0` попадает в последний интервал, замкнутый справа. Для `p = 1` и
  исхода 0 теперь `1.0` вместо `0.0` (#12).

- `forecast_verification` и `forecast_verification_delta`: коэффициент порога 0.647 заменён на 0.674
  (вероятное отклонение нормального закона, в источнике 0,674); значение вынесено в константу
  `PROBABLE_ERROR_COEFFICIENT` модуля `hydrometrics.backends.numpy` (#33, D1). Доля оправдавшихся
  прогнозов выросла: на данных `test_baseline_values` `forecast_verification` 0.9954 → 0.9982,
  `forecast_verification_delta` 0.4708 → 0.4836.
- `forecast_verification*`: пропуск в наблюдении, прогнозе или пороге даёт NaN вместо 0, при всех NaN
  результат NaN; тип поэлементного результата изменился с `int` на `float` (1.0, 0.0, NaN) (#20).
- `ssigma`: при постоянных наблюдениях результат NaN вместо `inf` (#21).
- `nse`, `log_nse`, `nnse`, `modified_nse`, `r2`, `ssigma`, `ssigma_delta`, `nse_variance_weighted`:
  дисперсия, равная нулю с точностью до округления (CV < 1e-12), считается нулевой; результат NaN вместо
  чисел порядка −1e+29 (#21). Допуск: константа `ZERO_VARIANCE_RTOL = 1e-24`.
- `log_nse`: пары с `obs + eps <= 0` или `sim + eps <= 0` считаются пропусками в обоих рядах, без
  `RuntimeWarning`; прежний результат на примере отчёта `obs=[−1,1,2,3]` (1.0) сохранён (#47).
- `accuracy`: пары с NaN исключаются, а не считаются ошибкой классификации; при всех NaN результат NaN
  вместо 0 (#22).
- `edi`, `sedi`: вырожденные частоты (H или F равны 0, для SEDI также 1) дают NaN без `RuntimeWarning`;
  значения при регулярных частотах не изменились (#25).
- `regNSE`: пропуски удаляются попарно до построения ранжированных кривых; NaN только в `sim`
  больше не приводит к ошибке, при NaN в `obs` пары теперь согласованы (#19).

#### Пропуски, оси, веса, бэкенды (этап 4, `docs/_dev/DESIGN_NAN_AXIS.md`)

- **`nan_policy` одинакова на всех бэкендах (#1–#6, D6).** Умолчание везде `"omit"` (на numpy было
  `"propagate"`). `omit` удаляет пары попарно, в том числе при `axis`, для ансамблей и для метрик с
  дополнительными массивами. `propagate` даёт NaN для результата или для срезов вдоль `axis`, где есть
  NaN (раньше NaN молча игнорировался и пары не согласовывались: `pearson_r` на данных отчёта 0.8689 при
  `propagate` и 0.8862 при `omit`). `raise` вызывает `ValueError` на всех бэкендах (на pandas, polars,
  xarray политика раньше не действовала). Неизвестная строка вызывает `ValueError`. Результат на данных
  без NaN не изменился.
- `nan_info["n_nan_removed"]` равно числу действительно удалённых пар (`omit`), при `propagate` и `raise`
  равно 0; на pandas, polars, xarray теперь тоже считается (#9 списка свойств).
- `validate_inputs(nan_policy="omit")` больше не выпрямляет массивы и не удаляет элементы: он ставит NaN
  в `obs`, `sim` и вес на недействительных парах и сохраняет форму. Код, рассчитывавший на 1-D результат,
  нужно изменить.
- **Имена весов (D7).** `sample_weight` каноническое имя, `weight` алиас на всех бэкендах; обе формы
  сразу вызывают `TypeError`. xarray: `dim` каноническое, `axis=` принимается и переводится в имена
  измерений; `dim` и `axis` вместе вызывают `TypeError`.
- **Метрики без весов и без оси (D8, #14).** При переданном `sample_weight` теперь `NotImplementedError`:
  `spearman_r`, `kendall_tau`, `roc_auc`, `pr_auc`, `ssigma`, `ssigma_delta`, `forecast_verification`,
  `forecast_verification_delta`, `regNSE`, `nse_variance_weighted` (раньше веса молча игнорировались).
  При заданной оси `NotImplementedError`: `ssigma_delta`,
  `forecast_verification_delta`, `regNSE`, `nse_variance_weighted`.
- **`reduction` (D10).** При заданных `axis`/`dim` без явного `reduction` возвращается массив по
  оставшимся измерениям (было `"mean"` на numpy), без оси `"mean"`. Явный `reduction` действует на всех
  бэкендах (раньше на pandas, polars, xarray игнорировался) и для каждого значения словаря
  (`kge_components`). Неизвестное значение вызывает `ValueError`.
- **`kge_2009`, `kge_2012` (#7, D11).** На pandas, polars, xarray возвращают `MetricResult` со скаляром,
  а не кортеж. `kge_components` на xarray возвращает `MetricResult` со словарём, а не словарь
  `MetricResult`.
- **Формы результата при оси (#8, #9).** `nrmse`, `pbias`, `pearson_r`, `kge_*`, `alpha_component`, `rsr`,
  `sharpness` (в том числе с весами) дают форму `(n,)`, а не `(1, n)`; `nrmse` и `pbias` при `axis=1` больше
  не падают.
- **Ось у рангов и интервалов (#10, #11, #13).** `spearman_r`, `kendall_tau`, `roc_auc`, `pr_auc`,
  `reliability` считают каждый срез отдельно (раньше ошибка или один общий скаляр). В `reliability`
  знаменатель считает только действительные пары.
- **xarray (#28–#30).** `dim` работает для всех метрик с осью; результат `DataArray` с координатами
  оставшихся измерений; несколько измерений сворачиваются вместе; порядок измерений `sim` и весов
  выравнивается по именам. `Dataset` вызывает `NotImplementedError` (ветка раньше была недостижима).
- **`sentinel` (D13).** Работает на numpy и заменяет значения только в `obs` и `sim`; на pandas, polars,
  xarray `NotImplementedError` с пояснением (раньше `TypeError` без пояснения). Ложное утверждение о замене
  в `sample_weight` убрано из докстрингов.
- Единая проверка форм: несовпадение длин даёт `ValueError("Shape mismatch ...")` на всех бэкендах
  (на pandas раньше была ошибка numpy о вещании).
- Скалярный результат всегда числовой скаляр numpy; у `r2` вместо 0-мерного массива (`str(result)`
  печатал `array()`).
- Метаданные результата (`name`, `direction`, `bounds`, `reference`, `meta`) теперь одни и те же на всех
  бэкендах, потому что берутся из одного объекта. Например, `edi` на pandas, polars, xarray имел границы
  `(-1/3, 1)`, теперь `(-1, 1)`; названия вроде `"KGE 2009"` стали `"Kling-Gupta Efficiency 2009"`;
  `norm_source` и `meta["description"]` теперь заполняются на всех бэкендах.

#### Метаданные и документация API (этап 5)

- **`direction="target"` и `optimum` (D14).** У `bias`, `pbias`, `alpha_component`, `beta_component`,
  `gamma_component`, `kge_components` значение `direction` теперь `"target"`, у объекта метрики и у
  `MetricResult` появился атрибут `optimum` (0 для `bias` и `pbias`, 1 для остальных), `to_dict()` содержит
  ключ `"optimum"`. Код, сравнивавший `direction == "minimize"` для `bias` или `"maximize"` для
  компонентов KGE, нужно изменить. `MetricResult` принимает `"target"`; прочие значения по-прежнему
  вызывают `ValueError`.
- **`bounds` по фактическому диапазону (D14).** `beta_component`, `gamma_component`, `kge_components`:
  `(None, None)` (при отрицательных средних отношения могут быть отрицательными; было `(0, None)` и
  `(-1, 1)`); `sharpness`: `(0.0, 0.25)` для вероятностей (было `(0, None)`).
- `inspect.signature(hm.nse)` и `help(hm.nse)` показывают реальные параметры метрики и общие
  `axis`, `nan_policy`, `sample_weight`, `weight`, `reduction`, `sentinel` (было `(obs, sim, **kwargs)`).
- Докстринги метрик содержат общие параметры и раздел `Raises` (формируются в `core/docs.py` из одного
  текста); утверждения «Not supported» для весов и оси теперь верны. Исправлены описания
  `mean_annual_hydrograph` (имена и порядок параметров), `mean_annual_hydrograph_duration_curve`
  (позиции рангов, а не календарные дни), `regNSE` и `_reg_nse_core` (опорная кривая это кривая
  обеспеченности среднего годового гидрографа), `ssigma_delta` и `forecast_verification` (что
  возвращается) (раздел 5.4).

#### Группировка (этап 6)

- `compute_grouped`: имена столбцов `obs` и `sim` разрешаются и для `xarray.Dataset` (раньше `IndexError`);
  несовпадение числа строк данных и кодов групп даёт `ValueError` (раньше `IndexError` из маски).
  Остальные ограничения (ключ NaN, дополнительные массивы, polars по именам, `to_xarray` для нескольких
  переменных, словарные метрики) не менялись и зафиксированы тестами `xfail(strict=True)`; см.
  `docs/_dev/BACKLOG.md`.

#### Решения автора (`task_3.txt`)

- **`ssigma` считается вдоль оси.** Результат имеет форму без оси (раньше на pandas и polars `(1, n)`, на numpy
  ось игнорировалась). Срез с `n <= m` действительными парами или с постоянным `obs` даёт NaN; без оси
  по-прежнему `ValueError` при `n <= m`. `NotImplementedError` для оси у `ssigma` отменён.
- В `hydrometrics.__all__` добавлены `registry`, `mean_annual_hydrograph`,
  `mean_annual_hydrograph_duration_curve`; написана страница `docs/api/helpers.rst`; у `BackendRegistry` и его
  методов появились докстринги.
- Предупреждения о расхождении с σ_Δ источника убраны из докстрингов `ssigma_delta`, `forecast_verification`,
  `forecast_verification_delta`: формулы подтверждены автором, коэффициент 0.674 верный.

#### Решения автора (`task_4.txt`)

- `ssigma` и `ssigma_delta` проверяют `m`: конечное неотрицательное число. Отрицательное, NaN и inf дают
  `ValueError`, не число (строка, `None`, список, `bool`) `TypeError`. Раньше принималось любое значение.
- `brier_score` и `reliability` проверяют входы: `obs` только 0 или 1, `sim` в [0, 1] (NaN не проверяется),
  иначе `ValueError`. Раньше значения вне диапазона принимались. `sharpness` не проверяется.
- `reliability`: `n_bins` должно быть целым не меньше 1 (`ValueError` иначе; раньше `n_bins=0` давал 0).
- `regNSE` и `mean_annual_hydrograph_duration_curve`: единое правило при високосном годе, усредняются 365-й
  и 366-й ранги. Раньше кривая режима усредняла 60-й и 61-й ранги, годовые кривые последние два. На данных
  `tests/test_baseline_values.py` `regNSE` изменилась с -10.8765 до -11.0644.
- `reliability` учитывает веса и в средних по интервалам (взвешенные средние вероятности и частоты), а не
  только в весе интервала. Результат с весами изменился; без весов нет. Вес 2 теперь равен повтору пары,
  вес 0 исключению пары.
- `edi` и `sedi` возвращают 1 при `H = 1`, `F = 0` (раньше NaN). Остальные вырожденные случаи без изменений.

### Удалено (task_5, этап A)

- Параметр `sentinel` удалён из всех метрик, из `validate_inputs` и из всех бэкендов (решение автора E1,
  пункт 19 KNOWN_ISSUES). Вызов с `sentinel=` даёт обычный `TypeError`; заменяйте коды пропуска на NaN до
  вызова. Записи ниже про `sentinel` (task_2, D13) оставлены как история.
- Метрика `nnse` переименована в `nse_bounded` (решение автора E2): функция, запись в реестре, `__all__`,
  поле `name` результата (теперь `Bounded Nash-Sutcliffe Efficiency`), страница документации. Алиас не
  оставлен. Формула прежняя, `NSE / (2 - NSE)`; значения не изменились. В литературе имя nNSE используется для
  формы `1 / (2 - NSE)`, это другая величина.

### Изменено поведение (task_5, этап B)

- Новый общий параметр `align` (`"strict"` по умолчанию, `"inner"`) у всех метрик и у `compute_grouped`
  (решение автора E4, пункт 7 KNOWN_ISSUES). По умолчанию два объекта pandas с неравными индексами или два
  `DataArray` с несовпадающими координатами (по измерениям, где координаты есть с обеих сторон) дают
  `ValueError` с первым расхождением и подсказкой. Раньше такие ряды считались по позиции без ошибки: код,
  который молча полагался на это, теперь падает. Входы разных типов, polars и numpy не проверяются.
- `align="inner"` оставляет общие метки в порядке `obs` до обработки пропусков; дубликаты меток, пустое
  пересечение и входы без меток дают `ValueError`. Число отброшенных строк (из `obs` и `sim` вместе) лежит в
  `result.meta["n_dropped_by_align"]`, в `parameters` появляется `align`.

### Изменено поведение (task_5, этап D)

Ошибки `compute_grouped` теперь понятные и с подсказкой, как обойти (пункты 2–6 KNOWN_ISSUES). Новые функции
не добавлялись.

- Пропуск (NaN, `None`, NaT) в группирующей переменной даёт `ValueError` (решение автора E5). Раньше каждый NaN-ключ
  молча образовывал отдельную группу, а `None` одну общую: это молчаливо неверный результат.
- Метрики с дополнительными массивами (`regNSE`, `ssigma_delta`, `forecast_verification_delta`,
  `nse_variance_weighted`) и аргументы длиной в число строк (веса, `norm`, `ref_forecast`) дают
  `NotImplementedError` (раньше непонятный `ValueError` о форме).
- Метрики, возвращающие словарь или массив (`kge_components`, расчёт по `axis`, поэлементный результат), дают
  `NotImplementedError` (раньше `TypeError` из `float()`).
- Объекты polars и имена столбцов polars дают `TypeError` с примером передачи массивов; имена столбцов без
  таблицы pandas или Dataset xarray дают `TypeError`.
- `GroupedResult.to_xarray()` для нескольких группирующих переменных даёт `NotImplementedError` (раньше
  `ValueError` из xarray); подсказка: `to_pandas()`.

### Изменено поведение (task_5, этап E, упаковка)

- Обязательная зависимость только `numpy`. pandas, polars, xarray и scipy стали необязательными:
  `pip install hydrometrics[pandas]`, `[polars]`, `[xarray]`, `[scipy]` или `[all]`. Набор `[all]` раньше означал
  `dev` и `docs`; теперь это три бэкенда и scipy. Добавлены наборы `test` и `crosscheck`.
- `import hydrometrics` работает без pandas, polars и xarray; бэкенд, чьего пакета нет, просто не регистрируется.
  `spearman_r` и `kendall_tau` импортируют scipy при вызове и без него вызывают `ImportError` с подсказкой.
- `hydrometrics.__version__` берётся из метаданных пакета (единый источник: `pyproject.toml`).

  Legates & McCabe (1999) как на первоисточник формулы (D4, см. `docs/_dev/UNVERIFIED_REFS.md`).
